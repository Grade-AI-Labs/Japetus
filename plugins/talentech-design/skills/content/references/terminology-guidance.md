# Terminology guidance for source copy

Source: Confluence — **Terminology and approved language**.

This skill applies terminology but does not maintain the glossary.

## Priority

Use terminology in this order:
1. Shared Talentech terminology for common platform concepts.
2. Approved domain/product terminology for genuinely specific concepts.
3. Reviewed legacy terminology when no approved replacement exists.
4. Unapproved suggestions and old translations only as evidence/reference.

Shared terminology takes priority over legacy product wording when the concept is the same.

## Writing behavior

- Use one clear term for one concept when meaning is the same.
- Do not introduce synonyms just for variation.
- Prefer words users understand without internal company knowledge.
- Avoid internal project names and technical implementation language in user-facing copy.
- Do not use one term for multiple distinct concepts.
- Do not retain legacy wording only because it already exists.
- Do not translate product/feature names unless an approved localized form exists.
- Use sentence case for feature/function names unless an approved brand name differs.

## If terminology is unclear

When a word could refer to different concepts, use context instead of lexical similarity. If the available context does not resolve the concept, flag the ambiguity or ask for clarification rather than inventing a product-specific meaning.

When a new shared term appears to be needed, do not silently establish it in source copy. Flag it for terminology review. The separate Talentech Terminology workflow should define the concept, preferred term, avoided variants, domain, context, and translations.
