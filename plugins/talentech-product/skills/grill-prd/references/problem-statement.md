# Stage 1: problem statement

No solution language anywhere in this stage.

## Checklist

Every topic is a required branch. Settle it, or agree with the user to defer it as Open with a reason.

- **Problem**: the problem in one sentence, with no solution in it.
- **Who**: the segment, role, product, market and sector that has it. User, buyer and anyone affected, if they differ.
- **Evidence**: how we know (interviews, analytics, support tickets, lost deals), with a source for each claim. Data apart from opinion. One anecdote is not a pattern: ask for the second data point.
- **Cost of not solving it**: to the user and to the business.
- **Why now**: what changed, and why not six months ago or six months from now.
- **Current state**: how it is handled today (tools, workarounds, manual steps), and what has been tried before.
- **Root cause**: why the problem exists, as far as we know.
- **Job to be done**: the underlying job, apart from any feature idea.

## Template

Write every field. If one has no answer, write `Open — <reason>` or `N/A — <reason>`.

```markdown
# Problem statement: <short title>

**Problem:** <one sentence, no solution>

**Who has it:** <segment, role, product, market, sector; user / buyer / affected, if they differ>

**Evidence:**
- <claim> — <source> (<data | opinion>)

**Cost of not solving it:** <to the user> / <to the business>

**Why now:** <what changed>

**Current state:** <how it is handled today; what was tried before and what happened>

**Root cause:** <why it exists>

**Job to be done:** <the underlying job>

**Open:**
- <topic> — <reason> — <who could answer>
```
